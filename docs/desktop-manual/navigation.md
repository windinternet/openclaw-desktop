# Desktop 导航能力

涉及当前仓库内容、路径、写入规则或项目目标时，必须以 Repository Context 和仓库 `AGENTS.md` 为准。

## Dashboard

Dashboard 用于观察当前实例、工作系统推进状态、Gateway 状态、Agent、会话、用量、最近产物、ActionRun 和仓库摘要。当前首屏已先展示“我的工作系统”摘要，把 Sessions、Workbench、Knowledge、ActionRun、Artifacts、Repository `outputs/index.md`、`runs/action-runs/index.md` 和 `reviews/` 复盘文档中已有事实聚合成今日继续、待确认、卡住事项、最近成果、本周新增成果和知识动态；其中本周新增成果来自当前 UTC 周创建的 Artifact outputs、仓库 output index 条目、本周完成的 ActionRun 结果摘要，以及本周更新复盘中明确 `成果` / `产物` / `输出` / deliverable 小节里的列表项。旧仓库 output 索引没有 `createdAt` 时回退使用 `updatedAt`，仓库 output 条目会跳转到 `/workbench?view=outputs`，ActionRun 摘要条目会跳转到 `/workbench?view=actions`，复盘成果线索会跳转到 `/workbench?view=reviews`。Dashboard 最近成果和本周新增成果会把带 `reuseKind` 的 Artifact 与 Repository output 标为“可复用资产”，并展示复用分类、最近执行状态或待审批边界。Dashboard 不从复盘全文做语义推断。卡住事项会读取计划中的 `status: blocked/stuck/卡住`，也会读取显式 `blockedReason` / `blocker` / `阻塞原因` 和 `blockerOwner` / `负责人`，并把这些事实展示在卡住项详情中；计划显式写出 `dependsOn`、`dependencies`、`依赖事项`、`关联事项` 或 `前置事项` 时，会作为 `plan:cross-work-risk` 跨事项依赖风险进入卡住项；工作事项前部显式写出同类依赖字段时，会作为 `work:cross-work-risk` 工作事项依赖风险进入卡住项并打开对应事项预览。已在 `completedWork`、`completedPlans`、默认 `work/completed/` 或 `plans/completed/`，以及安全语义映射 completed 目录段（如 `10-ops/tasks/completed/*.md` 或 `10-ops/plans/completed/*.md`）中出现的依赖会从风险详情中过滤，只展示仍未完成的依赖。未完成依赖如果 14 天没有更新，会在详情中标记“停滞 N 天”；未完成的活跃计划依赖如果没有显式 `owner` / `负责人` / `blockerOwner` 元数据，会标记“负责人未知”；未完成工作事项依赖如果在事项前部显式写有 `owner`、`负责人` 或 `责任人`，会在风险详情中显示负责人。工作事项 `## 收尾动作` 的未勾选项也会进入“待确认”。Dashboard 会把这些尾动作分类为 `tail-action:status`、`tail-action:output`、`tail-action:knowledge` 或 `tail-action:review`，分别导向 Workbench 状态处理、Artifacts、Knowledge 或 Workbench 复盘后续，并在目标 URL 携带 `tailAction`、`tailActionId` 和 `workItemPath`。已归属事项的终态 ActionRun 如果没有出现在 `runs/action-runs/index.md`，也会作为 `action-run:unarchived` 待确认进入 Dashboard，并打开 `/workbench?view=actions`；终态 ActionRun 如果没有 `workItemPath`，会作为 `action-run:unassigned` 待确认进入 Dashboard，详情显示 `workItemUnassignedReason`，并同样打开 `/workbench?view=actions`；已完成且有 `resultSummary`、有 `workItemPath`、没有 `artifactIds` 且没有 Artifact source 指向该 run 的 ActionRun，如果没有被同事项未完成成果尾动作覆盖，会作为 `action-run:output-unpreserved` 待确认进入 Dashboard，打开 Artifacts 的 `tailAction=output` 成果沉淀入口。这些都是观测和提醒，不会自动创建事项、修复仓库索引、修改运行记录、推断计划正文或事项正文风险、自动创建产物。Artifacts 会用这些上下文打开 AI 产物创建入口，并为成果类尾动作或成果沉淀缺口预填来源事项和沉淀意图；用户显式保存产物后，Desktop 会把 Artifact 或 Repository output 链接写入来源事项 `## 关联成果`，并只在 `tailActionId` 指向事项 checklist 时完成匹配成果尾动作；Knowledge 会显示来源事项上下文，并可发起携带 `workItemPath` / `tailActionId` 的 `knowledge_rewrite` ActionRun，要求先读取来源事项、关联执行记录、关联成果和现有知识库，写入前仍需审批且不会自动勾选知识尾动作；Workbench 状态类尾动作会显示“状态收尾动作”卡片，可显式选择 `active` / `blocked` / `done` / `paused` 并更新来源事项 `status`、完成匹配尾动作，当来源事项已经是 `done` 且位于当前绑定工作根的 active 目录时，用户可显式点击“归档完成事项”移动到同一工作根的 completed 目录（默认如 `work/active/*.md -> work/completed/*.md`，语义映射如 `10-ops/tasks/active/*.md -> 10-ops/tasks/completed/*.md`）；Workbench 复盘视图会在复盘类尾动作进入时显示“复盘收尾动作”卡片，保留来源事项、`reviews/weekly/` 目标和 `desktop.artifacts.execution.review.write` 命令线索，并可写入事项复盘草稿；用户显式确认草稿后，Workbench 会把草稿标记为 `confirmed`、写入 `reviewedAt`，并只勾选匹配来源尾动作；Dashboard 也允许用户标记完成、写回事项 Markdown。Dashboard 写回只勾选该条收尾动作，不自动移动事项文件、更新知识库、Artifact 执行复盘或资产权限变更。当 Gateway 已连接但本地工作仓库不可用时，Dashboard 会前置“创建你的工作系统”引导，让用户选择工作空间：继续体验、新建推荐结构、绑定已有仓库、映射或改造已有仓库。Setup / Welcome 连接成功后会进入 `/?onboarding=work-system`，让 Dashboard 绕过默认首页偏好并定位到工作系统开箱路径。用户可以先跳过仓库初始化进入临时会话；仓库就绪后，Dashboard 或临时事项卡片会让用户输入或保存“第一件事”，写入当前绑定工作根下的 `active/YYYY-MM-DD-HHmmss-*.md` 工作事项（默认如 `work/active/*.md`，语义映射如 `10-ops/tasks/active/*.md`），并进入 Workbench。Gateway 健康状态仍可见，但不应成为回答“我的系统现在怎么样”的唯一或优先内容。

## New Session

New Session 是用户发起新事情或继续工作台事项的入口。它可以进入普通聊天，也可以承接开箱“先体验”路径的临时事项上下文；该路径本身不写仓库、不把临时对话伪装成长期事实源。仓库就绪后，New Session 的临时事项卡片可以把第一件事显式写入当前绑定工作根下的 active 事项（默认如 `work/active/*.md`，语义映射如 `10-ops/tasks/active/*.md`），并进入 Workbench 事项预览。具体聊天页的临时事项卡片会先尝试通过 `sessions.get` 拉取完整 Gateway 会话历史，失败或为空时回退当前可见消息，再把会话归档为 `sources/imported/*-temporary-session.md` 并链入事项 `## 关联资料`；写入事项包含“临时会话承接”、资料/成果/知识/复盘后续核对清单，以及归档消息中的明示成果、知识和复盘线索。该入口仍不自动生成计划、不执行 ActionRun、不沉淀成果、不写 Wiki/index/log、不确认复盘。

## Artifacts

Artifacts 面向所有有价值的成果和可复用资产，包括报告、文档、链接、文件、HTML、工具、脚本、模板和工作流。带 `reuseKind` 的 Artifact 会作为可复用资产进入搜索索引；用户可在 Artifacts 页面直接搜索“可复用的脚本”、“可复用的模板”、“可复用的工具”或“可复用的工作流”，也可通过复用分类筛选按全部复用、通用资产、模板、工具、脚本和工作流缩小列表；仓库 output 镜像会把带 `reuseKind` 的条目同步写入 `outputs/assets/index.md`，让仓库内也有第一片可检索资产目录；仓库内已有脚本、模板、流程、HTML 或其他价值资产可通过 `desktop.repository.assets.record` 以仓库相对路径登记到同一个资产目录；Gateway 可通过 `desktop.artifacts.search` 查 Artifact storage，也可通过 `desktop.repository.assets.search` 查 Repository 资产索引，两者都支持普通中文可复用资产查询；当仓库本地 `tool / script / workflow` 已由外部 runner 审批、运行或完成时，可通过 `desktop.repository.assets.execution.record` 写入 `runs/assets/` 记录、维护 `runs/assets/index.md`，刷新 `outputs/assets/index.md` 的最近运行和复盘线索，并在传入当前绑定工作根下安全 `workItemPath` 时把资产执行追加到事项 `## 执行记录` 与 `## 收尾动作`；状态、成果、知识和复盘四条尾动作都会保留同一 `runs/assets/*.md` 链接。搜索和描述结果会返回 `assetExecutionSummary` 或结构化资产索引线索，让 Gateway 看到执行型资产是否需要审批、最近执行状态/结果/输出线索、终态执行后的复盘建议，以及 Desktop 只记录、不执行、不授予权限的边界；用户或 Gateway 确认复盘内容后，可通过 `desktop.artifacts.execution.review.write` 写入 `reviews/weekly/` 复盘。搜索、筛选和资产索引只返回已有产物线索，不打开文件、不执行命令、不自动写复盘、不授予权限。通过 `action-run-output:<runId>` 进入成果沉淀时，Artifacts 会加载来源 ActionRun，并用 `buildArtifactOutputPreservationPrompt` / `extractActionRunOutputCandidates` 把结果摘要里的显式文件、链接、HTML、文档、表格或演示候选带入 AI 创建初始提示；这仍只是提示上下文，不自动保存产物。

Dashboard 和 Workbench 会通过 Workbench Snapshot 读取 `runs/assets/index.md`：资产运行结果会进入最近成果和本周新增成果，`review: pending` 会作为 `asset-run:review-pending` 待确认进入 Workbench reviews。Workbench 资产运行详情会根据同一条运行记录里的 `repositoryOutputPath` / `outputArtifactId` 标记“成果已沉淀”，或根据终态结果摘要但缺少输出线索标记“成果待沉淀”；activity 资产运行列表也会显示该成果状态，并可筛选全部成果、待沉淀或已沉淀。对于 `status: approval_required / approved / denied` 的运行索引条目，Workbench 会显示“待审批 / 已批准 / 已拒绝”并支持全部审批、待审批、已批准或已拒绝筛选；待审批运行详情还会提供 approved / denied 两条审批决定记录命令，并在命令里带 `sourceApprovalRunPath` 回链当前待审批运行。如果后续 approved / denied 事实在 `runs/assets/index.md` 写有 `sourceApprovalRunPath`，待审批详情会优先精确匹配该字段，显示“已记录批准决定 / 已记录拒绝决定”和对应运行记录路径，并停止展示重复的审批决定命令；旧索引没有该字段时才兼容同一资产 id/path 匹配。终态 `succeeded / failed / cancelled` 运行事实也优先按 `sourceApprovalRunPath` 精确回流到原待审批运行，旧终态记录没有该字段时才兼容同一资产 id/path；待审批详情会显示“已运行成功 / 运行失败 / 运行已取消”、对应运行记录路径、时间和结果摘要，也停止展示重复审批决定命令。列表层也会展示后续终态运行的成果状态，并按后续终态运行计算有效成果筛选状态，让旧审批记录进入正确的待沉淀或已沉淀筛选。列表层也会按 confirmed 复盘文档计算有效待复盘筛选状态，待复盘标签和筛选都会按 confirmed 复盘文档后的有效状态显示，让已有确认复盘的资产运行不再停留在待复盘筛选或全部列表的待复盘标签里；同时会用 `getRepositoryAssetRunEffectiveReviewState()` 区分待复盘、复盘草稿和已复盘，可按全部复盘、待复盘、复盘草稿或已复盘筛选。Desktop authorization 卡片也可以在用户点击 approve / deny 后，用当前 ready 仓库和明确资产 id/path 记录同一类 approved / denied 事实。这只是观测、路由与事实记录，不自动写复盘、不执行资产、不授予权限，也不自动创建 Artifact 或 Repository output。

Workbench 预览仓库本地执行型资产时，会显示“审批操作 / Approval Action”，提供 `desktop.repository.assets.execution.record` 的 `approval_required` 记录命令，并透传 `approvalTitle`、`approvalRisk`、`approvalReason` 审批上下文，方便 Gateway 或外部 runner 在执行前写入审批意图。该入口只复制记录命令，不执行资产、不授予权限。

## Workbench

Workbench 面向事项、计划、运行记录、成果和复盘。它读取当前绑定工作根、当前绑定计划根、`runs/`、`outputs/` 和 `reviews/`；默认仓库可对应 `work/` 与 `plans/`，语义映射仓库可对应 `10-ops/tasks/` 与 `10-ops/plans/`。预览工作事项时，Workbench 可以从该事项直接发起 `work_matter_plan` ActionRun 生成计划草案，带上来源 `workItemPath` / `workItemId`，并要求写入当前绑定活跃计划根前先请求审批；默认仓库使用 `plans/active/<slug>.md`，语义映射仓库可使用 `10-ops/plans/active/<slug>.md`。审批块携带 `repositoryWrite` 时，Action Center 批准后会校验安全路径、写入计划 Markdown，并把计划链接回来源事项 `## 关联计划`。预览活跃计划时，Workbench 可以发起 `plan_execute` ActionRun 执行计划；只有计划元数据里的安全 matter-like `workItemPath` 被当前 Workbench Snapshot 识别时，Desktop 才会带入来源事项上下文和 frontmatter id；终态后继续走运行记录和事项收尾动作机制。Workbench 会用 `findLatestPlanExecutionRun` 按 `planPath` 把最近一次 `plan_execute` 关联回计划，在活跃计划列表和预览头部展示状态/摘要，并提供进入 Action Center 的入口；如果最近一次执行已完成、有 `resultSummary`、有安全 `workItemPath` 且没有 `artifactIds`，`shouldOfferPlanExecutionOutputPreservation` 会在预览头部显示“沉淀成果 / Preserve Output”，并打开 Artifacts 的 `tailAction=output`、`tailActionId=action-run-output:<runId>` 和来源事项上下文；如果最近一次执行已完成、有 `resultSummary` 且有安全 `workItemPath`，`shouldOfferPlanExecutionKnowledgeUpdate` 会在预览头部显示“更新知识 / Update Knowledge”，并打开 Knowledge 的 `tailAction=knowledge`、`tailActionId=action-run-knowledge:<runId>` 和来源事项上下文；同样满足条件时，`shouldOfferPlanExecutionReview` 会在预览头部显示“写复盘 / Write Review”，并打开 Workbench reviews 的 `tailAction=review`、`tailActionId=action-run-review:<runId>` 和来源事项上下文。计划执行入口不会自动创建产物、写 Wiki/index/log、勾选事项尾动作或确认复盘；“沉淀成果”、“更新知识”和“写复盘”都只进入显式后续流程。预览工作事项也可以发起 `artifact_create` ActionRun 沉淀成果。当 Dashboard 状态类尾动作进入 Workbench tasks 视图时，Workbench 会显示“状态收尾动作”卡片；用户可选择 `active`、`blocked`、`done` 或 `paused`，确认后只更新来源事项 Markdown 的 `status` 并勾选匹配状态尾动作，状态更新本身不移动事项文件。当来源事项已经是 `done` 且位于当前绑定工作根的 active 目录时，用户可显式点击“归档完成事项”，Workbench 会把它移动到同一工作根的 completed 目录；默认如 `work/active/*.md -> work/completed/*.md`，语义映射如 `10-ops/tasks/active/*.md -> 10-ops/tasks/completed/*.md`。该入口不沉淀成果、不更新知识库、不写复盘。当 Dashboard 复盘类尾动作进入 Workbench reviews 视图时，Workbench 会显示“复盘收尾动作”卡片，提示用户核对执行记录、成果和知识变更，并把确认后的复盘写入 `reviews/weekly/`；卡片会暴露 `desktop.artifacts.execution.review.write` 命令线索，也可先创建 `reviews/weekly/YYYY-MM-DD-work-*-tail-action-*-review.md` 事项复盘草稿。计划执行复盘入口也会进入这个视图，但 `tailActionId=action-run-review:<runId>` 只表示来源执行记录，不是事项 checklist ID；它可创建复盘草稿，并把草稿链接写回来源事项 `## 复盘`，不会显示“确认复盘并完成尾动作”。草稿只提供核对清单和正文框架，并会链接回来源事项 `## 复盘`，创建时不会自动确认复盘、更新事项或勾选尾动作；用户显式确认真实尾动作草稿后，Workbench 会写入 `status: confirmed` 和 `reviewedAt`，并只勾选匹配来源尾动作。

Workbench 计划预览会避免重复后续入口：如果同一来源事项下已经有未失败/未取消的 `knowledge_rewrite` ActionRun，且输入包含 `action-run-knowledge:<runId>`，同一个计划执行不再显示“更新知识”；同时计划预览会通过 `findPlanExecutionKnowledgeUpdateState` 显示最新同源知识更新状态，包括知识更新中、知识待审批、知识已更新、知识无需写入、知识更新失败或知识更新取消。如果复盘文档 frontmatter 已记录同一 `workItemPath` 和 `sourceExecutionId` / `tailActionId: action-run-review:<runId>`，同一个计划执行不再显示“写复盘”。当已有同源知识更新且仍可写复盘时，计划预览会把复盘入口显示为“复盘知识更新 / Review Knowledge Update”，仍进入 `action-run-review:<runId>` 复盘上下文。计划预览还会通过 `findPlanExecutionReviewState` 把同源复盘文档显示为“复盘草稿 / Review Draft”或“已复盘 / Review Confirmed”，只表达既有草稿或已确认事实。这只是入口去重和上下文提示，不会自动写 Wiki、确认复盘或完成事项尾动作。

创建计划执行来源的复盘草稿时，Workbench 会把同源、未失败/未取消且输入包含 `action-run-knowledge:<runId>` 的 `knowledge_rewrite` 运行写入草稿 `relatedKnowledgeRunIds`、正文和核对清单。用户复盘时可以检查知识更新是否已写入 Wiki/index/log 或确认无需写入；Desktop 不会因此自动写知识库或确认复盘。

## Knowledge

Knowledge 面向资料源和长期 Wiki。它对应仓库中的 `sources/`、`wiki/`、`wiki/index.md` 和 `wiki/log.md`。

当前 Knowledge Snapshot 会生成健康报告，检查孤立资料、未进入索引的 Wiki、陈旧索引条目、知识库内断链、无来源引用 Wiki、长期未复盘事项、结构化事实矛盾、自由文本能力矛盾和显式标记的相互矛盾记录。长期未复盘事项来自当前绑定工作根下 active/someday 事项与 `reviews/weekly/` 的交叉检查；默认仓库可对应 `work/active/` / `work/someday/`，语义映射仓库可对应 `10-ops/tasks/active/` / `10-ops/tasks/someday/`。Knowledge 页面可通过“健康检查”视图查看，Dashboard 知识动态也会显示这些问题并跳转到 `/knowledge?section=health`，用户还可以把当前健康报告写入 `reviews/weekly/YYYY-MM-DD-knowledge-health.md`。

Knowledge 已提供“导入文本”、“导入文件”、“导入文件夹”、拖拽导入和“剪藏 URL”入口，可把用户粘贴的原始资料、本地 Markdown/MDX/TXT/LOG/CSV/TSV/JSON/JSONL/YAML/TOML/INI/CONF/PROPERTIES/SQL/GraphQL/Proto/JavaScript/TypeScript/CSS/Python/Shell/HTML/XML/RTF/RST/AsciiDoc/SRT/VTT/PDF/Word/Excel/PowerPoint/SVG/图片/音频/视频文件、文件夹中的同类资料、网页链接、可选摘录以及无摘录时的 best-effort 抓取片段写入 `sources/imported/`，刷新后进入“未消化资料”视图。Markdown / MDX / TXT / LOG / CSV / TSV / JSON / JSONL / YAML / TOML / INI / CONF / PROPERTIES / SQL / GraphQL / Proto / JavaScript / TypeScript / CSS / Python / Shell / HTML / XML / RTF / RST / AsciiDoc / SRT / VTT 会直接作为文本资料读取；RTF 不渲染富文本、不解析控制字、不抽取嵌入对象，RST / AsciiDoc 不渲染文档、不解析指令、不展开 include，SRT / VTT 不代表自动转写音视频；PDF 与 Word/Excel/PowerPoint OOXML 会 best-effort 抽取文本；旧版 Word .doc 可在 macOS 上通过 textutil best-effort 抽取，旧版 Excel 会尝试 BIFF8 结构化/printable-text best-effort 抽取，旧版 PowerPoint 会尝试 TextHeaderAtom text atom/printable-text best-effort 抽取，并在存在 SlideContainer/NotesContainer 时按 # Slide N / # Notes N 小节分节，制表符表格行会保留为 tabular text，SVG 会抽取显式文本；抽取失败的旧版 Office、栅格图片、音频和视频会记录 `extractionStatus: unavailable` 及 `image-ocr-unavailable`、`audio-transcription-unavailable`、`video-transcription-unavailable` 等原因。JSON / JSONL / YAML / TOML / INI / CONF / PROPERTIES / SQL / GraphQL / Proto / HTML / XML / RTF / RST / AsciiDoc / SRT / VTT 只作为文本资料读取，不做 schema 推断、不自动写 Wiki/index/log。剪藏 URL 在无手填摘录且 Electron URL fetching 可用时，会 best-effort 抓取网页标题和正文片段，并记录 `urlFetchStatus`、`## 网页抓取内容` 和 `## 抓取边界`；失败或不支持内容类型时仍保留 URL source。

Knowledge 会把未进入索引、也未被 Wiki 引用的资料源放入“未消化资料”视图，可通过 `/knowledge?section=digest` 打开并发起单条资料消化 ActionRun。Dashboard 知识类尾动作进入 Knowledge 时，会显示来源事项并提供“发起知识更新 ActionRun”，创建带 `workItemPath` / `tailActionId` 的 `knowledge_rewrite` ActionRun；该 ActionRun 要求先读取来源事项、关联执行记录、关联成果和现有知识库，写入前仍需审批。计划执行知识更新入口也会进入 Knowledge，但 `tailActionId=action-run-knowledge:<runId>` 只表示来源执行记录，不是事项 checklist ID；它可发起 `knowledge_rewrite`，不会显示“确认已处理并完成尾动作”。完成真实知识尾动作或确认无需写入后，用户可在 Knowledge 显式确认尾动作，Desktop 只勾选来源事项中匹配的知识尾动作。健康检查和未消化队列不自动改写仓库，修复仍需通过 Knowledge ActionRun 或 repository tools 走审批。

## Collaboration

Collaboration 面向 Agent Teams、3D Office 和多 Agent 协作活动。涉及创建或调整 Agent 团队时，先生成计划，必要时通过 ActionRun 和审批执行。

## Control Center

Control Center 面向 Gateway cron tasks、技能、插件、工具、Agent 调教、Repository Protocol 和实例设置。涉及 Desktop Companion、插件管理、仓库协议同步时，优先在这里暴露状态和手动动作；仓库协议页的 Desktop 操作手册同步会显示内容 hash、最后同步时间、同步通道和逐 Agent 写入状态。
